외부 최소단위 조사 검토와 적용 판단
==================================

검토일: 2026-09-06. [외부 보고서 수신본](/Users/carlos-yang/dev/fireworks-simulator/research/external-research/fireworks-simulation-granularity-research.ko.md)을 읽고, 추가 자료 일부를 직접 확인했다. 수신본은 외부 ChatGPT가 작성한 분석이고, 이 문서는 로컬 검토다. 아래 권고는 구현 전 설계 후보이며 확정된 스키마나 검증된 엔진 사양이 아니다.

**사용자가 정한 타임라인 모델은 그대로 성립한다.** JSON은 시작 시각·발사대·효과 자산·설정·seed를 담고, 런타임은 트리거된 효과의 운동과 외관을 계산한다. 되감기는 필요한 입력을 다시 실행해 목표 시각의 상태를 복원하면 된다. 중간 스냅샷은 탐색 속도를 위한 선택 사항이다. 상세 동작은 [타임라인·런타임 모델](/Users/carlos-yang/dev/fireworks-simulator/research/timeline-runtime-model.ko.md)에 분리했다.

**1. 최소단위 질문의 답은 ‘무엇을 독립적으로 편집하고 움직이게 할 것인가’에 있다.**

그램은 질량의 단위이고, 원료 알갱이·성형된 발광체(star)·분리된 불티·렌더 입자는 서로 다른 대상이다. 이번 문헌으로 전 효과에 공통인 실제 최소 입도나 질량 기준을 확정할 수 없다. 외부 보고서도 그런 기준을 찾았다고 주장하지 않는다. 실제 배합이나 용기 충전 구조를 예측하는 실물 모델은 조사 범위에 포함하지 않았다.

관람용 시뮬레이터의 출발점으로는 **하나의 독립 궤적과 발광 수명을 가진 가상 발광체**를 편집 가능한 기본 개체로 두는 안이 적절하다. 이는 논문에서 유일한 최소단위로 증명한 결론이 아니라, 관찰 가능한 결과와 편집 동작을 연결하기 위한 설계 추론이다. 모든 발광체의 내부 재료 입자를 계산해야 한다는 근거는 없다.

| 사용자가 바꾸려는 것 | 편집 원본의 후보 | 별도 운동 상태가 필요한 경우 | 화면 표현 |
|---|---|---|---|
| 구형 불꽃의 일부 위치·색·수명 | 분포 그룹과 선택한 발광체 ID | 발광체마다 독립 궤적을 가질 때 | 발광점과 짧은 궤적 |
| 길게 남는 꼬리 | 부모 발광체와 꼬리 프로필 | 불티가 부모 경로에서 벗어나거나 독립적으로 남을 때 | 경로 리본, 필요한 불티점 |
| 가지가 갈라지는 효과 | 분기 규칙과 특정 자식 ID | 부모·자식의 생성 시점과 궤적을 구분할 때 | 가지와 발광점 |
| 연속적으로 나오는 불티 | 생성기와 시간별 방출·외관 곡선 | 생성된 불티가 각자 이동할 때 | 점·짧은 선분·원거리 집합 표현 |

예를 들어 사용자에게는 ‘발광체 하나와 꼬리 하나’로 보이더라도, 계산은 부모 한 개와 필요한 자식들로 하고, 렌더러는 더 많은 선분을 그릴 수 있다. 편집 개체 수와 화면 표본 수를 같게 정할 이유는 없다. 색·밝기 변화·발광 지속·꼬리·분기 외관을 미세 조절하는 항목은 가상 시각 프로필로 묶을 수 있다.

**2. 좌표는 ‘가상 위치·방향·목표’ 중 무엇을 뜻하는지 먼저 구별해야 한다.**

초기 위치만 저장한다고 완성된 모양이 결정되지는 않는다. 운동 방향, 상대 속도, 발광 시점과 수명, 분기, 카메라 투영이 함께 관여한다. 외부 보고서의 `initial-position`, `direction-sample`, `target-position` 구분이 이 혼동을 줄인다.

특히 **개체를 드래그했을 때 운동 방향도 바꿀 것인지**는 편집기에서 명확히 해야 한다. 외부 JSON 예시는 원래 분포의 방향을 유지하고 위치만 바꾼다. 이 규칙은 사용자가 기대하는 ‘배치를 바꾸면 펼쳐지는 모양도 달라진다’와 다를 수 있다. 기본 편집 동작으로 확정하기 전에 위치와 방향의 연결 방식을 선택해야 한다.

정규화된 자산 좌표를 세계 좌표와 분리하고, 가상 발사대 변환은 생성 시점에 읽는 안은 타임라인 모델과 잘 맞는다. 발사대가 나중에 회전했다고 이미 분리된 공중 효과가 함께 회전해서는 안 된다. 지속 부착된 효과는 별도 규칙이 필요하다. 외부 보고서의 축·쿼터니언 순서·변환 순서는 제안이며 기존 엔진과의 호환성이 검증된 계약은 아니다.

비균일 크기 변형을 지원한다면 추가 판단이 필요하다. 방향에 회전만 적용하는 규칙은 위치와 속도 모두에 같은 비균일 변형을 적용하는 규칙과 결과가 다르다. 조형만 변형할지, 운동도 함께 변형할지 정해야 한다. 이 선택은 외부 보고서 §4.2의 일반적인 변환 설명만으로 확정하지 않는다.

**3. 저장은 생성 규칙과 개별 수정의 조합을 후보로 삼을 수 있다.**

전체 분포는 규칙·seed·생성기 버전으로 표현하고, 사용자가 수정한 개체 K개의 위치·외관만 따로 저장하는 방식이다. 단순한 생성기 설명의 크기를 P라고 하면 원본 규모는 O(P+K)다. 모든 좌표를 저장하면 O(N)이다. 규칙으로 작게 저장해도 N개를 만들어 움직이는 런타임 비용이 없어지는 것은 아니다. 임의 메시나 복잡한 마스크의 데이터 크기도 P에 포함해야 한다.

수정 보존에는 다음 구분이 필요하다.

- 고정 ID는 ‘같은 개체’를 식별한다. 동일 좌표까지 보장하지는 않는다.
- N과 무관한 표본열의 앞 N개를 쓰는 생성기는 증원할 때 기존 좌표를 유지할 수 있다. N에 따라 전체 배치를 다시 맞추는 생성기는 다르다.
- 절대 local 좌표 수정은 자산 안의 위치를 고정한다. 상대 오프셋 수정은 새로 생성된 기본 위치를 따라간다.
- 개체 감소·삭제 시 나머지를 재번호화하면 수정 대상이 바뀐다. 비활성 개체의 수정을 보존하거나 명시적으로 정리해야 한다.
- 생성기나 분포 구조를 바꿨을 때 수정 대상이 없어지는 문제는 seed만으로 해결되지 않는다. 좌표 고정 또는 사용자가 확인할 재연결 동작이 필요하다.

독립적인 난수 주소 지정은 이 구조의 재현성을 도울 수 있지만, 전체 배치 변경 후 편집 의도를 보존하는 정책까지 제공하지는 않는다. 이번 단계에서 특정 난수 라이브러리나 생성 알고리즘을 선택하지 않는다.

**4. 외부 보고서에 보충할 데이터 수명 조건이 있다.**

보고서 §6의 리본 이력 비용 O(A(t)H)는 현재 살아 있는 운동 노드만 A(t)에 포함한다면 부족할 수 있다. 부모가 소멸한 뒤에도 꼬리 이력이 남는 모델이 있기 때문이다. 보존 중인 궤적 수를 별도로 Q(t)라 두면 이력 비용을 O(Q(t)H)로 설명하는 편이 명확하다. 이는 구현 측정치가 아니라 누락을 막기 위한 데이터 모델 보충이다.

원본 JSON에 꼬리의 매 순간 좌표를 영구 저장할 필요는 없다. 다만 현재 프레임을 그리는 데 과거 경로가 필요하다면 런타임에 이력을 보존하거나 다시 구성해야 한다. ‘렌더용 데이터’라는 이유만으로 모든 데이터를 현재 위치 한 점에서 즉시 복원할 수 있다고 가정하면 안 된다.

선택적 재생 캐시를 도입할 때는 자산·엔진 버전 외에도 큐와 설정의 변경, seed, 관련 환경 입력, 캐시 시각이 유효성 판단에 포함되어야 한다. 외부 보고서의 캐시 설명은 개요이며 완성된 캐시 키 사양이 아니다. Wasm·GPU 분업, 압축, 캐시 간격과 수치 상한은 후속 구현과 측정에 남긴다.

Cui 논문은 형상의 특징을 드러내는 표본화와 목표 위치에 맞춘 애니메이션을 제안한다. 여기서 얻는 근거는 ‘목표 모양을 제어하는 CG 모델이 존재한다’는 것이다. 논문에서 사용한 표본 수를 모든 불꽃의 정확한 최소 개체 수로 채택할 근거는 아니다. [저자 측 대학 공개본](https://graphics.cs.uh.edu/wp-content/papers/2020/2020-CAVW-SketchFireworkSimulation.pdf)

PBRT의 표본화 절은 가상 좌표를 의도한 분포로 생성하는 근거다. 영상 형성 절은 노출과 카메라 감도가 관측 밝기에 섞인다는 근거다. 이 자료들이 실제 불꽃 내부를 복원하는 정확도를 검증한 것은 아니다. [표본화](https://www.pbr-book.org/4ed/Sampling_Algorithms/Sampling_Multidimensional_Functions), [영상 형성](https://pbr-book.org/4ed/Cameras_and_Film/Film_and_Imaging)

외부 참고문헌 R3의 DOI 중간에는 미리보기의 자동 링크가 들어가 있다. 복사해서 조회할 때 사용할 완전한 DOI는 `10.4028/www.scientific.net/AMR.505.287`이다. 수신본은 그대로 보존했다. 전체 출처별 외부 열람 기록은 수신본 §9에 있으며, 최초 [출처 목록 JSON](/Users/carlos-yang/dev/fireworks-simulator/research/sources.json)의 24건과 별도로 관리한다.

**6. 구현 전에 검증할 것은 관람 조건에서 필요한 상세도다.**

현재는 어떤 개체 수와 모델이 충분한지 실측한 결과가 없다. 고정된 원본으로 카메라와 재생 시점을 바꾸면서 정면 윤곽, 펼침과 소멸의 시간 변화, 여러 시점의 일관성, 반복·되감기 재생의 동일성을 각각 판단해야 한다. 같은 seed로 똑같이 재생되는 것과 실제 관측을 닮는 것은 다른 검증 항목이다.

남은 설계 판단은 기본 편집 개체와 프로필 범위, 위치 편집과 운동 방향의 연결, 개수·분포 변경 시 수정 보존 정책이다. 리본만으로 충분한 조건과 독립 불티가 필요한 조건은 관람 거리·카메라·영상 자료로 확인해야 한다. 외부 보고서에 등장한 제안 모드나 수치 예시를 자동으로 제품 요구사항에 추가하지 않는다.
