## React 갱신 확인

개발용 `?diagnostics`의 버튼으로 재생 전후에만 수치를 읽었습니다. React StrictMode의 초기 두 번 커밋을 포함합니다. 약 21.7초 공연을 끝까지 재생한 구간입니다.

| 컴포넌트 | 재생 전 | 재생 후 |
| --- | ---: | ---: |
| App | 2 | 2 |
| CanvasHost | 2 | 2 |
| Header | 2 | 2 |
| Library | 2 | 2 |
| Inspector | 2 | 2 |
| EffectInspector | 2 | 2 |
| StarEditor | 2 | 2 |
| Timeline | 3 | 3 |
| TimeReadout | 4 | 223 |
| Transport | 4 | 6 |

시간 표시는 진행 중 갱신되고, 재생 버튼은 시작/종료에만 갱신됐습니다. 앱 본체나 편집 패널이 매 프레임 다시 그려지지 않는 것을 확인했습니다. 이는 렌더 횟수 확인이며 정식 FPS·CPU·메모리 프로파일링은 아닙니다.

최종 컴포넌트 분리 후 개수를 200→201로 바꾼 추가 확인에서는 `EffectInspector`만 2→3이 되었고, `App`·`CanvasHost`·`Library`·`Inspector`·`StarEditor`·`Timeline`은 2를 유지했습니다. 기존 목록 행과 공유 발광체 편집기에 `memo`를 적용하고 행은 실제로 표시하는 이름·색·패턴만 구독합니다.

## 화면 비교 기록

참조: `docs/design/studio-concept.png`. 제작용 앱을 참조의 원래 크기인 1536×1024에서 IAB의 네이티브 스크린샷으로 캡처했습니다. 참조와 최종 캡처를 같은 확인 과정에서 `view_image`로 각각 열어 직접 비교했습니다. 실제 사용자 입력을 처리하는 화면으로 구현했고, 참조 이미지를 앱의 화면이나 불꽃으로 사용하지 않았습니다.

| 비교점 | 개념 화면 근거 | 구현 화면과 조치 |
| --- | --- | --- |
| 화면 구성 | 상단 파일 메뉴, 왼쪽 라이브러리, 중앙 캔버스, 오른쪽 설정, 하단 타임라인 | 같은 영역과 순서 유지. 1280px에서도 편집하기 위해 패널 폭과 글자 크기는 화면 기준 문서의 값 적용 |
| 색과 배경 | 짙은 중성 패널, 검은 하늘, 앰버 선택 상태 | 토큰과 공통 스타일로 적용. 패널을 카드 묶음으로 바꾸지 않음 |
| 문구 | 불꽃 작업실, 5개 패턴 이름, 파일/타임라인 조작 | 기본 이름 유지. 실제 공유 편집에 필요한 ‘공유’, 이름·복제·추가와 단독 미리보기는 의도한 추가. 초 단위 ‘꼬리 길이’는 ‘잔광 지속’으로 정정 |
| 서체와 숫자 | 산세리프 편집 UI, 시간 숫자, 제목의 강조 | 시스템 한국어 폰트, 공통 12–17px 편집 크기와 고정 폭 숫자 적용. 제목·필드·메뉴를 각각 확인 |
| 간격과 제어 요소 | 얇은 테두리, 낮은 둥근 모서리, 행 단위 선택 | 공통 필드/버튼으로 통일. 설정 패널의 불필요한 세로 여백을 줄이고 내용이 많을 때 내부 스크롤 허용 |
| 아이콘과 발광체 안내 | 선형 파일/시간 아이콘, 형태별 아이콘, 구형 와이어 안내 | Lucide 및 코드로 만든 패턴/구형 SVG. 선택 색과 선의 크기를 공유 |
| 불꽃과 무대 | 중심의 금색 불꽃, 잔광, 약한 바닥 격자 | 실제 3D 점과 궤적으로 표현. 국화형 잔광을 늘려 펼쳐지는 선을 보강. 미리보기에는 단일 원점, 공연에는 설치한 발사대 표시 |
| 타임라인과 모바일 | 3개 발사대 행과 5개 큐 | 큐 길이는 분기/잔광을 포함한 계산값. 공연 눈금은 25초까지 늘어나며 미리보기 시간 탐색은 별도 표시. 모바일은 패널 선택과 세로 배치, 44px 조작 버튼 적용 |

첫 화면 문구 비교에서 이름·메뉴·패턴명은 유지됐습니다. 추가/변경된 문구와 공간 배치는 `docs/design/ui-spec.md`에 기록한 실제 편집 기능에 해당합니다. 참조의 화면 구성과 시각 체계를 기준으로 구현을 검증했으며, 불꽃 궤적·파생 수치와 위의 기능상 변경은 의도된 차이입니다.

개발 중 함수 컴포넌트를 `memo`로 바꾸는 순간 기존 탭의 HMR에서 `Component is not a function` 오류가 기록됐습니다. 전체 새로고침 후 정상 화면·렌더 진단을 확인했고, 최종 새로고침 이후 새 오류/경고는 없었습니다. 최종 제작용 빌드의 새 로드에서도 오류는 없었습니다.

## 아직 하지 않은 검증과 제한

- Rust/Wasm, Worker, 공유 메모리 구현·검증은 하지 않았습니다. 현재 엔진은 TypeScript입니다.
- 독립 Chrome/Firefox/Safari, 실제 모바일 기기, 스크린리더 전 과정은 확인하지 않았습니다.
- 최대 24개 큐/표시점 상한에 대한 장시간 부하, 메모리 누수 프로파일링, FPS 측정은 하지 않았습니다.
- 실제 불꽃 관측과 대조하는 물리·연소 모델 검증은 하지 않았습니다.
- Three.js를 포함한 지연 로딩 청크는 약 553.70 kB (gzip 139.31 kB)로 빌드의 500 kB 안내가 남습니다. 청크를 분리해 UI와 별도로 로드하지만 초기 그래픽 로딩 비용은 후속 측정 대상입니다.
- 카메라, 선택 항목, undo 이력은 JSON에 저장하지 않습니다. 개별 발광체 좌표 편집과 타임라인 드래그 등 후속 기능은 README에 구분했습니다.
