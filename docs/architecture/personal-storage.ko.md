# 개인 보관함과 프로젝트 저장

앱은 서버를 사용하지 않고 브라우저의 IndexedDB에 개인 작업을 보관한다. 같은 브라우저라도 `localhost`와 `127.0.0.1`은 서로 다른 origin이므로 보관함도 따로 만들어진다.

| 저장소 | 내용 |
| --- | --- |
| `projects` | 공연 문서와 프로젝트 이름·시각 |
| `presets` | 사용자가 저장한 내 프리셋 스냅샷 |
| `assets` | 해시 ID로 중복을 없앤 이미지 격자 |
| `meta` | 현재 선택된 프로젝트 ID |

`projects`에는 현재 작업 중인 공연 문서와 이름, 생성·수정 시각을 저장한다. 프로젝트 안의 내 불꽃은 이 프로젝트에만 속한 작업 사본이다. `presets`에는 사용자가 따로 보관한 내 프리셋 스냅샷을 저장한다. 프리셋을 프로젝트에 추가하면 새 작업 사본이 만들어지므로 이후 어느 쪽을 고쳐도 다른 쪽은 바뀌지 않는다.

이미지 기반 불꽃은 `assets`에 한 번만 저장한다. 각 자산은 내용 해시 ID를 가지며, 레이어는 그림 데이터를 복사하지 않고 `assetId`, 2D·3D 배치, 외곽·채움·디테일·외피 부분을 참조한다. 같은 그림을 여러 프리셋, 내 불꽃, 큐에서 쓰더라도 자산은 중복 저장되지 않는다. `meta`에는 현재 프로젝트 ID를 기록한다.

변경된 프로젝트는 잠시 묶어 자동 저장한다. 저장 실패나 다른 탭의 더 새 저장본과의 충돌은 화면에 남으며 다시 저장할 수 있다. 이때도 현재 화면의 공연 JSON과 전체 백업은 메모리의 최신 작업에서 만들 수 있다. 이전 localStorage 원본은 IndexedDB로 옮긴 뒤에도 남겨 둔다.

각 탭은 저장을 시도하기 전에 동기 복구 저널을 남긴다. 저장이 끝나도 프로젝트 ID와 토큰이 모두 일치하는 저널만 지우므로, 늦게 끝난 저장이 더 새 편집 내용을 지우지 않는다. 복구 시 저장본의 revision이 바뀌었거나 프로젝트가 휴지통에 있으면 기존 저장본을 보존하고 복구 내용을 새 사본으로 만든다.

| 용도 | 최상위 형식 |
| --- | --- |
| 단일 불꽃 | `{ kind: "fireworks-firework/1", version: 1, firework, assets }` |
| 공연 | `{ kind: "fireworks-show/1", version: 1, show, assets }` |
| 전체 보관함 | `{ kind: "fireworks-library/1", version, projects, presets, assets, archivedProjects }` |

현재 공연 JSON은 `fireworks-show/1`로 문서와 필요한 자산만 내보낸다. 단일 불꽃 JSON은 `fireworks-firework/1`, 전체 보관함 백업은 `fireworks-library/1`이며 모든 프로젝트·내 프리셋·휴지통·자산(사용하지 않는 자산 포함)을 함께 저장한다. 불꽃·공연 파일은 5MiB, 전체 백업은 64MiB까지다. 내보낼 때도 같은 한도를 확인하므로 앱이 스스로 가져올 수 없는 파일을 만들지 않는다. 큰 백업은 공연별 파일로 나누어 보관한다. 가져오기는 자산 해시와 스키마를 먼저 검증한 뒤 새 프리셋·프로젝트 사본만 추가한다. 누락된 자산, 알려진 형식의 지원하지 않는 버전, 잘못된 참조는 아무것도 쓰지 않고 거절한다. 현재 프로젝트와 기존 항목은 덮어쓰거나 삭제하지 않으며, 저장된 프로젝트 선택기로 원하는 사본을 연다. 배포되는 앱에는 사용자가 만든 그림, 이름, 프리셋, 예시 보관함을 넣지 않는다.
